## 1 实施与能力复用

本批只把既有账号与安全能力接入 UI-C/D 已使用的列表、详情、确认和恢复方式。账号、成员和设备仍是各自的领域对象；管理目标不改变认证身份。没有新增端点、密码协议、认证因素或通用写入幂等层。

| 文件 | 本批改动与复用 |
| --- | --- |
| `web/management/accounts.tsx` | 全局账号筛选与详情、状态和密码确认、密码清理、持续反馈与原账号恢复；复用 UI-D 的 `CreateAccount`，该组件实现保持不变 |
| `web/management/devices.tsx` | 四态列表、详情、解绑及原因校验、设备/绑定互斥、原设备/绑定回读和明确结束核对；复用已有操作标识与回执恢复 |
| `web/management/sessions.tsx` | 会话列表、单条撤销、按目标域/用户批撤、真实数量、锁定原用户逐页核对与明确结束 |
| `web/management/audit.tsx` | 平台/目标域真实审计、筛选重置、游标、结构化异常、原始变更详情及 UTC 时间说明 |
| `web/management/diagnostic.tsx` | 既有诊断确认、实际 decision/audit ID、未知结果禁止重放与明确允许新查询 |

## 2 契约落实

| 任务 | 边界、确认与恢复 |
| --- | --- |
| 全局账号状态 | Enabled 明示“平台与所有租户（共享账号）”，Disabled 为本系统；不与局部成员暂停混淆。摘要包含账号 ID、邮箱及原/新状态；沿用 `expected_status`。pending 可由管理员确认启用，closed 只读。停用退役各域凭证，启用不恢复旧凭证；最后有效管理员由原服务端规则保护，409不推断具体领域原因 |
| 全局改密 | 明示各域 session、refresh、授权码与未完成选择退役。密码仅在表单内短暂保留，确认、URL、存储与运行图片不含密码；取消、重读、提交结束、关闭和卸载清理。没有密码 CAS。未知改密不能靠账号 GET 解锁或证明新值，保留写锁；明确放弃后可离开，不自动重放 |
| 自身处置 | 沿用原 client 清凭证和会话 revision；成功改密/停用或撤销自身会话返回登录。迟到响应不能恢复旧工作区；不改宿主认证、Cookie 或跨标签协调协议 |
| 设备与人员解绑 | 保留 pending/active/disabled/revoked；无有效密钥不能启用，revoked不可恢复。停用退役设备关联凭证但保留密钥/绑定，启用不复活旧凭证；撤销另退役密钥并解绑全部人员。解绑仅原人员/设备关系，active与suspended可解绑，unbound终态。确认展示租户、设备、客户端、状态/版本及原绑定/用户；原因沿用非空、最多512 UTF-8字节、无控制字符规则 |
| 设备恢复 | 原 client 已有 `operation_id` 与回执查询，继续复用，不套用到其他接口。回执或最终对象读取失败时页面保守提示未取得完整结果；锁定原设备/绑定，读取失败保持锁定。原对象读取成功后仍须“结束设备核对”/“结束绑定核对”；当前状态不能证明请求归因。绑定读取/确认/未知结果阻止父设备写入，普通列表刷新不能解锁原绑定 |
| 会话撤销 | 单条仅 pending/active可撤，expired/revoked只读，原接口空请求体且无CAS。按用户批撤仅当前目标域、覆盖其全部客户端/设备的有效或待完成会话；不影响其他主体/域，不修改账号、设备或密钥。成功数量来自真实响应。未知批撤锁定原域/用户，成员GET不解锁；原用户会话逐页核对，失败重试当前页，到末页后明确结束；不从当前状态反推撤销数量 |
| 诊断与审计 | 诊断POST写审计，结果只说明查询时刻判断，不授予权限或证明资源存在。未知/拒绝后不自动重试；明确放弃并允许新查询时说明可能新增审计。审计沿用原平台/目标域接口、真实游标及原始change JSON，不补造before/after、IP或统计；记录以UTC显示，筛选按浏览器本地时区输入 |
| 通用交互 | 空、403、读取失败及成功后回读失败分别显示。有效写响应的成功信息持续保留；未知写入先核对原对象，不盲重放。草稿、确认层、待确认结果离页继续使用原壳层保护；忙时不可离开，明确放弃可关闭非写入中的读取。确认取消优先、内容可聚焦滚动，表格局部横滚，表单ID唯一 |

Fixed/Choose 非0会话不能通过URL进入平台账号能力；Disabled仍使用系统域0。UI中的可见状态或capabilities不是授权矩阵，最终由原管理接口校验。管理员专用处置抽屉及租户管理员/成员保护直接复用 UI-D，不增加普通角色绕过路径。

### 3.3 证据层级与调试记录

设备/绑定、pending/expired/closed等边界状态与批撤恢复的额外分页数据由脚本在验证过所有权的临时schema中定向种入；自身处置夹具另定向建立平台0成员关系，再用真实专用API任命临时管理员。没有提供产品中的平台成员补建入口。这不是实体设备登记或设备证明的端到端浏览器验收。账号、密码与管理员任命等使用真实管理API；设备状态/解绑、会话撤销、诊断与审计回读走真实HTTP。51条审计由真实诊断产生，没有SQL伪造审计。

丢响应用例先真实提交并独立GET确认，再中断页面响应；503、403、空响应和延迟为明确浏览器注入。跨标签用例真实退出后交付原完整响应。密码结果不可由账号GET证明；测试仅以独立审计/状态确认写入已执行，不向产品提供额外密码查询能力。

早期全量运行分别发现验收脚本未接受既有放弃确认、子绑定结束后过早读取父按钮状态，已修正等待/确认并重新完整运行；失败尝试不计通过。设备与会话模块曾独立探测通过，也不替代最终全量。截图核对又发现窄屏图片截在缩放动画初始帧，补充动画完成与实际宽度检查、禁用截图动画，并等待诊断确认层关闭后重跑；没有据缩小图片宣称窄屏通过。

回归调试中，既有UI-D脚本曾在权限被拒绝后的“核对”按钮定位超时；读取DOM确认原按钮仍disabled，但退场loading图标带入可访问名称。改为限定原表单footer的唯一primary按钮核对禁用属性，未放宽写锁要求。另一次选择控件等待也曾超时，改为按原控件ID重新取DOM，避免继续依赖可能失效的旧ElementHandle；继续精确检查原popup、选项、展开/关闭状态及最终标签。UI-B在已大量播种的共享夹具上曾发生第二次当前会话校验等待超时；此尝试不计通过，不推断为某项产品缺陷已修复。随后使用独立新夹具完整运行原UI-B脚本19组通过，原脚本未改。最终回归记录与失败尝试分别对待。

## 4 复跑方式

先按仓库约定构建Web，再构建 `embedded-idp-app` 和 `bootstrap_local_postgres` 示例。使用已安装的PostgreSQL18镜像运行 `python3 scripts/prepare_management_navigation.py --image <本机镜像ID>`，不拉取镜像。准备脚本返回私有state路径，含临时凭证，禁止提交或打印内容。

为浏览器脚本提供 `IDP_UI_TEST_FIXTURE`、已安装的 `IDP_UI_PLAYWRIGHT_PATH`、`IDP_UI_BROWSER_EXECUTABLE` 和私有 `IDP_UI_OUTPUT_DIR`，执行 `node scripts/check_management_security.mjs`；UI-B/C/D回归分别运行原导航、客户端与授权脚本。Rust真实数据库测试仅将临时state中的URI通过子进程环境传入 `EMBEDDED_IDP_TEST_PG_CONNECTION_URI`，不写入报告。

完成后执行 `python3 scripts/prepare_management_navigation.py --cleanup <原state路径>`；核对自建容器、四个宿主和临时目录均已移除。普通离线检查仍不依赖真实数据库。
