## 2 导航与隔离契约的落点

| 模式 / 登录范围 | 页面入口 |
| --- | --- |
| Enabled 平台0 | 工作台、租户管理、系统管理员、账号安全、客户端、平台权限、平台审计；保留原6个任务 |
| 平台0管理非0目标 | 工作台、成员、角色与权限、权限目录、诊断、设备、会话、审计；保留原7个目标域任务及页内管理员/账号操作 |
| Enabled Fixed/Choose非0 | 上述本租户任务；无平台菜单、任意目标选择或平台账号创建；真正Choose保留切换登录租户入口 |
| Disabled 系统0 | 工作台、原9个任务（角色/目录/成员/诊断/设备/会话/审计/账号/客户端），另直接提供既有系统管理员流程入口；无租户选择 |

地址为 `<ui-base>/#/platform/<page>`、`#/tenants/<id>/<page>`、`#/system/<page>`。只有页面与目标ID进入hash；筛选、业务草稿、邮箱、凭证和票据不写入URL或持久存储。对象详情继续使用页内抽屉，不增加不完整的对象深链接。

- 恢复/登录后先验证真实session，再装配工作区和读取页面。非0会话访问平台或其他租户的合法地址得到本地403，不发越界请求；未知页面、非法编码、额外路径段或编码斜杠得到局部404。精确的`.`、`..`仍按现有租户ID语法作为hash数据，不执行路径归一化；非0会话仍只能访问自己的ID。URL和Capabilities都不授予动作权限。
- 平台目标先调用原getManagedTenant；精确`.`/`..`使用已有`GET /admin/tenants?tenant_id=...&limit=2`，严格检查唯一、完整匹配且无后续页（空结果404，异常或无权限不当作不存在），避免HTTP dot段被浏览器归一化；读取失败/403/404不挂数据页，不自动换目标、不创建对象；有效暂停/归档状态按原数据展示。目标选择不调用Choose，不更换登录会话。非0登录只使用已认证的本租户ID，不越权补名称。
- 页面按hash重挂，工作区按tenant/account/session/client身份重挂；旧页面游标、筛选、详情和草稿不进入新页面。目标元信息请求用active上下文丢弃迟到结果；原client会话revision和页面现有卸载保护继续生效。
- 菜单、地址编辑、前进后退共用离页检查。管理写操作进入authenticated时即开始计数，包括凭据获取和共享refresh等待；响应/错误及会话取消均在finally释放计数，进行中禁止离开；可见业务弹层、已编辑的弹层/页内动作草稿、发生过写入的页面在离开前提示核对原目标。刷新/关闭由原生beforeunload提供尽力提示，最终是否显示由浏览器决定。
- 活动计数不判断领域成功/失败，不声称实现了结果查询或幂等协议。成功写入也会保守地提示一次；原页面负责显示已确认/未知结果。本次验收的未知结果保留原目标和仍打开的弹层错误，用户明确离开后丢弃；不自动重试、不跨目标重放、不持久化敏感字段。没有新增自动“已核对”判定或跨弹层的未知动作台账，原页面关闭弹层后的回读流程继续复用。
- 受本壳层标记且属于同一历史链的条目，取消导航按索引返回原条目；相同hash也同步历史位置。登录前/外部未标记条目的方向不可可靠确定，取消时原地恢复当前URL和草稿并建立新链。该兜底可能留下重复地址或替换那个未标记条目的URL，不保证保留未知历史的全部地址；不会猜方向继续退出页面。
- 普通403保留仍有效会话，普通401按原client清理认证并卸载工作区；sessionChanged显示独立重新加载恢复入口。局部403/404的侧栏使用当前合法route或已认证范围的fallback构造页面目标，错误地址不会使菜单失效，也不会把越界目标带入恢复跳转。restore/refresh失败、Cookie协调、开发模式过期及token用途隔离均服从原client，壳层不重放旧凭证。

### 3.3 检查中发现并处理的问题

1. 旧Rust资源测试依赖roles块名，壳层拆出后首次失败；更新为新的shell块，实际资源HTTP断言重新通过。

## 4 可复跑方式与隔离清理

先构建资源和程序，准备已安装的PostgreSQL 18镜像；脚本不会拉取镜像。Node环境需能导入已有Playwright并有相匹配的Chromium。仓库未增加依赖或lockfile变动。

```sh
pnpm --dir web build
cargo build -p embedded-idp-app --locked --offline
cargo build -p embedded-idp-storage-postgres --example bootstrap_local_postgres --locked --offline
python3 scripts/prepare_management_navigation.py --image <已安装的PostgreSQL18镜像>
```

准备脚本输出`fixture_file`及非敏感loopback地址；**不要cat该JSON**。它以owner-only文件保存测试密码、数据库URI、key和配置，生成全新容器/随机schema，不接受现有业务库。client准备是夹具显式播种，不是新模式启动自动补建；测试写入只在隔离数据中进行。

```sh
IDP_UI_TEST_FIXTURE=<上一步返回的state.json> \
IDP_UI_OUTPUT_DIR=<独立的验收输出目录> \
node scripts/check_management_navigation.mjs
```

若Playwright不在Node模块路径，可指定`IDP_UI_PLAYWRIGHT_PATH`为已安装包的`index.mjs`绝对路径；若需选择已有浏览器，可指定`IDP_UI_BROWSER_EXECUTABLE`。本次使用Codex已有Playwright及Chromium headless shell 1243，无下载/安装。初次环境路径指向缺失的旧浏览器版本后，改用已安装的匹配版本。

完成后（含中途失败）务必清理，先保留不含秘密的结果与截图。默认输出在夹具目录，cleanup会一并删除。清理核对容器label、临时目录及PID命令行，拒绝终止被复用的PID：

```sh
python3 scripts/prepare_management_navigation.py --cleanup <同一state.json>
```

本次最终夹具和早期临时夹具均已停止并删除；保留的只有版本化脚本、报告、合成数据截图与不含凭证的结果JSON。未将fixture JSON、URI、key、日志、Web产物或依赖目录加入交付。
