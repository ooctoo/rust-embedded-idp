# Postgres Schema Design v1

> 历史文档：早期无租户 PostgreSQL 设计。当前新部署使用 tenant_v3（crates/embedded-idp-storage-postgres/src/sql/tenant_v3.sql），不使用本文的无租户表集和默认 schema 作为新环境基线。

## Purpose

This document defines the planned Postgres storage shape for `rust-embedded-idp` before concrete DDL is added.

It is the design source for:

- migration files
- repository SQL in `embedded-idp-storage-postgres`
- later integration tests against a real Postgres instance

## Scope

This schema is for the current module scope only:

- local account registration and login
- auth session persistence
- OIDC client lookup
- device provisioning, registration, binding, and heartbeat
- reserved storage for refresh token and device nonce flows

It does not attempt to model:

- organizations or tenants
- RBAC
- social login
- SAML
- generic audit/event warehouses

## Schema Rule

- default schema name is `embedded_idp`
- host config may override the schema name
- all SQL in the adapter must qualify table names with the configured schema

## Storage Decisions

- host-facing business identifiers such as account, session, device, binding, refresh-token-record, authorization-code-record, and nonce ids should be generated as UUIDv7 values
- the Rust domain boundary continues to treat those identifiers as opaque strings
- the Postgres adapter stores entity ids and foreign keys in native `uuid` columns
- timestamps are currently stored as epoch seconds integers to match the current Rust storage adapter implementation
- status values are stored as stable snake_case text values rather than native Postgres enums for simpler extraction and future portability
- OIDC client redirect URIs are stored as JSON text in v1 to avoid adding a join table before a second query pattern proves necessary

## Tables

The v1 table set is:

1. `accounts`
2. `oidc_clients`
3. `auth_sessions`
4. `devices`
5. `account_device_bindings`
6. `refresh_tokens`
7. `authorization_codes`
8. `device_nonces`

## Table: `accounts`

Purpose:
Store local user accounts for registration and password-based login.

Columns:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | primary key, UUIDv7 generated by module/host id generator |
| `email` | `text` | unique, normalized by application before write |
| `password_hash` | `text` | module-owned Argon2id PHC string |
| `display_name` | `text null` | optional |
| `status` | `text` | `pending_verification`, `active`, `disabled` |
| `created_at_epoch` | `bigint` | unix epoch seconds |

Constraints and indexes:

- primary key on `id`
- unique index on `email`
- check constraint for allowed `status` values

## Table: `oidc_clients`

Purpose:
Store registered OAuth/OIDC client metadata used by auth and device flows.

Columns:

| Column | Type | Notes |
| --- | --- | --- |
| `client_id` | `text` | primary key |
| `client_name` | `text` | display label |
| `redirect_uris_json` | `text` | JSON array of redirect URI strings |
| `client_type` | `text` | `public_desktop`, `confidential_web` |
| `pkce_required` | `boolean` | must be true for public desktop clients |
| `client_secret_hash` | `text null` | required for confidential clients, null for public clients |
| `created_at_epoch` | `bigint` | reserved for future admin flows |

Constraints and indexes:

- primary key on `client_id`
- check constraint for allowed `client_type` values

Notes:

- v1 keeps redirect URIs embedded as JSON text
- v1 stores only the secret hash, never the raw client secret
- if redirect URI query patterns become richer later, split into `oidc_client_redirect_uris`

## Table: `auth_sessions`

Purpose:
Store login session state and refresh token rotation version.

Columns:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | primary key, UUIDv7 |
| `account_id` | `uuid` | foreign key to `accounts.id` |
| `client_id` | `text` | foreign key to `oidc_clients.client_id` |
| `status` | `text` | `pending`, `active`, `revoked`, `expired` |
| `created_at_epoch` | `bigint` | unix epoch seconds |
| `expires_at_epoch` | `bigint` | unix epoch seconds |
| `refresh_token_version` | `bigint` | monotonic rotation counter |

Constraints and indexes:

- primary key on `id`
- foreign key on `account_id`
- foreign key on `client_id`
- check constraint for allowed `status` values
- index on `account_id`
- index on `client_id`

## Table: `devices`

Purpose:
Store physical devices independent of any one account binding.

Columns:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | primary key, UUIDv7 |
| `client_id` | `text` | foreign key to `oidc_clients.client_id` |
| `device_name` | `text` | host-visible device label |
| `proof_key_id` | `text` | key identifier used by device proof |
| `status` | `text` | `pending`, `active`, `disabled`, `revoked` |
| `registered_at_epoch` | `bigint` | unix epoch seconds |
| `last_seen_at_epoch` | `bigint null` | unix epoch seconds |

Constraints and indexes:

- primary key on `id`
- foreign key on `client_id`
- check constraint for allowed `status` values
- index on `client_id`
- index on `proof_key_id`

Notes:

- `proof_key_id` should be unique once a device becomes active
- pending devices may exist before any user binding exists

## Table: `account_device_bindings`

Purpose:
Store the relationship between accounts and devices so a shared physical device can be used by multiple accounts over time.

Columns:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | primary key, UUIDv7 |
| `account_id` | `uuid` | foreign key to `accounts.id` |
| `device_id` | `uuid` | foreign key to `devices.id` |
| `status` | `text` | `active`, `unbound`, `suspended` |
| `bound_at_epoch` | `bigint` | unix epoch seconds |
| `unbound_at_epoch` | `bigint null` | unix epoch seconds |
| `last_authenticated_at_epoch` | `bigint null` | unix epoch seconds |

Constraints and indexes:

- primary key on `id`
- foreign key on `account_id`
- foreign key on `device_id`
- check constraint for allowed `status` values
- unique index on `(account_id, device_id, status)` for active rows or an equivalent conflict rule in storage logic
- index on `account_id`
- index on `device_id`

## Table: `refresh_tokens`

Purpose:
Reserve a normalized place for refresh token lineage and revocation when token material should not live only inside signed blobs.

Columns:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | primary key, UUIDv7 |
| `session_id` | `uuid` | foreign key to `auth_sessions.id` |
| `token_version` | `bigint` | version associated with this row |
| `issued_at_epoch` | `bigint` | unix epoch seconds |
| `expires_at_epoch` | `bigint` | unix epoch seconds |
| `revoked_at_epoch` | `bigint null` | unix epoch seconds |

Constraints and indexes:

- primary key on `id`
- foreign key on `session_id`
- unique index on `(session_id, token_version)`
- index on `expires_at_epoch`

Notes:

- this table is planned now so migration shape is stable
- current Rust service logic only requires `refresh_token_version` on `auth_sessions`
- write-path usage for this table can be enabled in a later slice without reshaping the schema

## Table: `authorization_codes`

Purpose:
Store short-lived OIDC authorization codes and PKCE material for one-time token exchange.

Columns:

| Column | Type | Notes |
| --- | --- | --- |
| `code` | `text` | primary key |
| `account_id` | `uuid` | foreign key to `accounts.id` |
| `client_id` | `text` | foreign key to `oidc_clients.client_id` |
| `redirect_uri` | `text` | exact redirect URI bound to this code |
| `scope` | `text null` | raw scope string |
| `nonce` | `text null` | OIDC nonce when present |
| `code_challenge` | `text null` | PKCE challenge |
| `code_challenge_method` | `text null` | `plain` or `S256` |
| `created_at_epoch` | `bigint` | unix epoch seconds |
| `expires_at_epoch` | `bigint` | unix epoch seconds |
| `consumed_at_epoch` | `bigint null` | one-time consumption marker |

Constraints and indexes:

- primary key on `code`
- foreign key on `account_id`
- foreign key on `client_id`
- check constraint for allowed `code_challenge_method` values
- index on `account_id`
- index on `client_id`
- index on `expires_at_epoch`

## Table: `device_nonces`

Purpose:
Store short-lived device bootstrap challenges and replay protection artifacts.

Columns:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | primary key, UUIDv7 |
| `device_id` | `uuid` | foreign key to `devices.id` |
| `challenge` | `text` | nonce or challenge body |
| `issued_at_epoch` | `bigint` | unix epoch seconds |
| `expires_at_epoch` | `bigint` | unix epoch seconds |
| `consumed_at_epoch` | `bigint null` | unix epoch seconds |

Constraints and indexes:

- primary key on `id`
- foreign key on `device_id`
- unique index on `challenge`
- index on `expires_at_epoch`

## Referential Behavior

- deleting an `account` should be restricted in v1 rather than cascading silently
- deleting an `oidc_client` should be restricted while sessions or devices still reference it
- deleting a `device` should be restricted while active account bindings still reference it
- deleting an `auth_session` should be restricted while refresh token lineage exists
- deleting an `account` should be restricted while active account-device bindings still reference it

## Seed Expectations

Before auth flows can work against a real Postgres instance, at least one `oidc_clients` row must exist.

Recommended first seed:

- one desktop public client
- `pkce_required = true`
- loopback redirect URI for local desktop callback

## Open Deliberate Simplifications

- `email` normalization is currently application-side, not database-side with custom operators or collations
- `password_hash` is stored as a single PHC string and does not try to split algorithm metadata into separate columns
- `redirect_uris_json` stays embedded for v1
- epoch seconds are used first; a later revision may move to `timestamptz` if that becomes materially better for query ergonomics
