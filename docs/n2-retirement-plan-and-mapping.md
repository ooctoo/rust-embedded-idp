# N2退役范围与覆盖映射

N2原有八套检查器和手动workflow面向完整管理界面巡检。当前仓库的CI目标收敛为UT、真实集成和六组关键浏览器E2E，因此删除旧workflow、套件驱动、全量manifest、Docker补验准备器及仅服务旧套件的检查器。历史执行报告和证据目录保持原样，继续作为各自SHA/环境的历史记录。

## 合同处置

| 旧N2合同类别 | 处置 | 当前责任层 |
| --- | --- | --- |
| 认证/退出拒绝及会话恢复边界 | 代表性高风险断言迁入 | E01；会话规则另由UT/真实HTTP集成覆盖 |
| Choose选择取消与完成、旧目标/迟到响应不能污染新作用域 | 迁入 | E02 |
| 角色/成员API前置数据、浏览器实例授权与回读、未知结果后回原范围 | 迁入 | E03/E05；规则和存储合同另由UT/集成覆盖 |
| 机密客户端确认/取消/提交后的无明文泄露与清输入 | 迁入 | E03；密钥保留/轮换/转公开等完整语义仍归既有UT/集成 |
| 创建租户unknown回读后继续锁定、后续角色失败不补偿删除租户 | 迁入 | E05；与客户端配置回读后可解锁的语义区分 |
| 已确认保存后的读取失败、null/404不能开放重复创建 | 迁入 | E05；持续观测POST到恢复结束，不仅统计注入route |
| 工具超时后清理子进程、fixture所有权校验、准备失败安全收尾 | 保留其通用工具回归 | `test_management_n2_tools.py` 中四项fixture/清理测试；通用进程合同由 `test_n2_ci_processes.py` 覆盖 |
| 全管理页逐页巡检、筛选/分页/排序和完整配置排列 | 明确退出持续验收保证 | 不逐项迁移；仅保留E01–E06代表性关键路径 |
| 所有安全/会话/客户端异常排列和大量网络故障注入组合 | 去重并缩小 | 核心规则归UT/集成，浏览器保留代表性拒绝和恢复合同；其余排列退出 |
| Mac/Linux容器与浏览器环境组合、完整H01执行门槛 | 明确退出当前CI目标 | 既有专项证据留档，不转换成长期CI要求 |
| 缩放与旁白、M1-03–06 | 不纳入当前范围 | 无活动验收任务 |

六组当前具体断言见[CI覆盖映射](ci-quality-coverage.md)。迁入表示选取关键合同，不表示旧N2全量等价覆盖。任何未来新增的管理界面全量验收需求应单独说明用户价值、责任仓库和执行频率后再立项。

## 共享资源保留

- `scripts/n2-ci/package.json` 与 `pnpm-lock.yaml` 为现有关键E2E提供锁定Playwright依赖，目录名暂时保留以避免无关锁文件变更。
- `scripts/n2_ci_runtime.py` 与 `scripts/test_n2_ci_processes.py` 服务普通CI的超时/进程组处理，继续保留。
- `scripts/prepare_management_navigation.py` 为日常E2E准备隔离参考宿主fixture，继续保留。
- `scripts/test_management_n2_tools.py` 保留四项fixture/清理测试，仅移除N2专属日志脱敏与Mac profile finalizer测试。

旧manifest和套件脚本不是当前回归入口。删除不触碰 `docs/design/n2/` 下的历史日志、清单、附件或执行报告，也不据此改写旧结果。
