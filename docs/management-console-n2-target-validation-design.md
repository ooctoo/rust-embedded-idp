## 1 上下文、目标与非目标

UI-A–F交付了既有管理任务、壳层导航、确认、异常与恢复体验。N1进一步提供客户端固定query精确查询、租户JSON集合PATCH，并补齐误登记、写后回读及dot-only离页/迟到响应专项。N1的新UI与新服务端配对要求、旧动态路径限制、客户端无CAS/删除及未知结果无法证明请求归因等边界继续有效。

现有证据主要来自本机Chromium headless、loopback、隔离PostgreSQL与参考宿主。需求方已确认R01：**Windows 11桌面Chrome/Edge＋macOS桌面Chrome为首批核心家族，Safari/Firefox为扩展候选**。这没有冻结具体版本、实体设备、读屏、服务端或嵌入组合，也没有形成目标环境通过声明。

N2的目标是在以后得到执行授权、相关决定和环境具备后，证明选定环境中的现有任务与安全不变量，明确支持声明能够覆盖的最小单元。本次只交付可独立审阅的准备方案、矩阵、断言及证据规则，不将这些方案写成已执行结果。

不纳入本轮：后台重新设计或更换组件库、MFA/step-up/恢复等新增社区能力、设备自助/实体扫码完整体验、统计/CAS/导出、性能与长时运行、备份恢复或生产代理部署。发现产品缺陷时登记并另行安排修复；不能在补验中默默扩大API、schema、配置装配或身份合同。

### 4.2 宿主交付面

| 行 | 建议补验合同 | 必须保留的界限 |
| --- | --- | --- |
| H01 | 参考后台：Enabled平台、Fixed非0、Choose、Disabled；非默认API/UI挂载；合法browser/UI组合 | 仍是开发参考宿主；新模式仅管理/只读启动与旧参考只补缺行为分开，不能因补验向新配置填非空business_entries |
| H02 | 若选定，真实宿主同源挂载管理Web资源及管理API | 记录唯一可信meta、资源地址、外层前缀、origin与认证；管理壳层不是npm已发布公共组件 |
| H03 | 选定Rust宿主直接调用Core或选装受认证管理router；仅API、browser无UI及browser＋UI依既有合同取适用行 | 无UI时视觉不适用；纯Core宿主验证可信上下文、权限/用途/租户等价服务合同，HTTP路由不适用；选用相应Axum管理router时核对适用的N1路径。旧通用admin_router与独立管理router职责不同，重叠路由隔离前缀及认证 |
| H04 | 真实React业务主入口消费者：EmbeddedIdentityClient＋EmbeddedAuth＋主入口样式 | 宿主提供React/React DOM `^19.1.0`并记录实际解析版本，主入口无antd/后台壳层必选依赖；业务角色不是管理凭证，资源真实存在与归属由宿主校验 |
| H05 | 真实React管理目录消费者：独立ManagementClient＋PermissionDirectory＋admin样式 | React/React DOM `^19.1.0`、antd `^5.29.3`及React19 patch `^1.0.3`记录实际版本；optional peer不表示管理入口可省antd/patch。宿主须证明现有认证生命周期与保守离页/属性切换协调可用，不能把宿主责任当作组件已公开的状态接口 |
| H06/H07 | 原生WebView/Electron/Tauri、同源iframe/Shadow DOM等均非当前已验证组合；跨站iframe/第三方Cookie登录为当前不支持 | 不从Rust可嵌入、React bundle或同引擎推导支持。若纳入，先评估合同；不放松同源、用途或证明规则 |

H04只导入主入口和相应样式；H05只导入管理子入口、其样式和必要peer，不要求整套后台CSS。两者在同一宿主共存也仍是两种身份用途，不能共用一个业务token作管理认证。包目前私有、未发布npm；代表宿主取用所核对的本地制品，不为补验擅自发布。

会话任务按实际选择的Cookie、显式token或development_login模式执行。完整Cookie模式核对恢复/refresh；开发模式核对其明确禁用和重载/到期重登。采用现有EmbeddedIdentityClient或ManagementClient的token模式时，仍有内存凭证、单飞refresh、响应身份核对、失败清会话与退出合同，不能只写成宿主任意自定生命周期；不强加Cookie restore、Web Locks或跨标签Cookie共享。自定义transport不豁免实际采用的client合同。类似地，纯Core没有的HTTP/DOM接口可以说明不适用，但可信认证上下文、用途及租户权限等价规则仍须验证；不能为了套用矩阵给宿主增加原本不需要的UI、browser或路由。

**H05协调能力须单独核实**：PermissionDirectory公开props只有client、tenant、business，草稿、确认、busy、未知结果和恢复进度是内部状态；当前没有对外状态回调或统一离页协议。tenant/business变化会重挂内部作用域，client本身不在该key中，不能把替换client视为自动清理所有编辑状态。实际ManagementClient的mutation快照可以辅助判断待写/写入记录，但不能完整表达组件草稿与未知恢复状态。D05应登记代表宿主已有的保守确认、待写阻止、身份失效卸载及重挂办法，并实测；若现有合同不足以做到要求，记录该宿主行未满足前提或实际失败，另行设计/授权所需增量，不在N2假设新props、全局守卫或自动状态发现已经存在。

### 4.3 避免无限组合与漏验

建议每个B01–B03核心行在H01完成登录四策略、导航、N1寻址、草稿/未知结果与会话隔离的公共必验主链；客户端、租户准备/成员授权、账号、设备/会话、审计等每条既有任务链在该浏览器至少有适用的正常路径与重要拒绝路径。全局处置不能用租户局部处置替代，Disabled与Enabled非0边界不能互相替代。

完整细分异常、破坏性分支和宿主主题等可按风险分配，但每个用例都应有“环境行→适用任务→新跑/复用及理由”映射，并由D07确认。H04/H05在其被选定的浏览器组合单独验收；若只选一个代表环境，只声明该环境，不能继承整个核心浏览器矩阵。底层事务/管理员保护可以复用已核对服务证据，目标浏览器仍须证明实际请求、提示及安全恢复，不重复建一套业务服务。

## 7 无障碍与视觉审阅方法

建议用[W3C WCAG2.2固定版本](https://www.w3.org/TR/2024/REC-WCAG22-20241212/)的相关A/AA条款组织任务检查，包括键盘/无陷阱、焦点顺序与可见/不遮挡、标签/错误/名称角色值、状态消息、颜色/对比度、缩放及重排；是否要求完整一致性范围由D04/D07明确。局部条款通过不能写成全站WCAG认证。规范说明页是解释资料，不代替规范；未来执行附实际条款、操作和判断。

200%文字缩放与重排分开设计：真实浏览器200%检查不能替代[1.4.10重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)的320等效CSS px要求；1280起始宽度的400%可形成该等效宽度，但仍须记录实际有效视口。需二维布局的数据表可局部滚动，表单、后果说明及单元格内文本不因此整体豁免。[2.5.8点击目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)按24×24 CSS px或适用间距/例外逐项核对，不把更高等级尺寸当作已确认本期门槛。

自动标签、布局及对比度检查用于发现问题；人工纯键盘、真实缩放和选定读屏负责完成实际任务。每个被选页面检查正常、加载、空/无匹配、校验错误、403/401、写入成功、未知结果、终态及相关弹层；不可只复验26个页面定位的默认截图。视觉审阅还应覆盖长标识/长文案、短窗口、Select展开、确认层滚动、按钮和焦点遮挡。

视觉候选沿当前浅色中文后台、React19/antd5及UI-A业务结构；不新增主题、语言或Pro模板。D06分别签认独立后台和代表嵌入主题，记录可接受的纯视觉差异。危险操作原目标/版本/后果、保护规则、恢复指引和敏感值隐藏均属于业务/安全合同，不能为贴近画板而删减。
