## 1 目标与范围状态

N0用于回答“准备对什么环境和交付面作何种承诺、需要什么证据、哪些决定还没有作出”。本文件不安排浏览器安装、实体终端测试、宿主改造、兼容修复或生产运行；这些动作不因本设计形成而获得授权。

当前可确认的是UI-A–F既定任务已完成本地交付。已有验收主要来自本机Chromium、loopback、隔离PostgreSQL和编译后参考宿主；不等同桌面Chrome/Edge/Safari/Firefox、实体设备或所有嵌入宿主均已通过。支持矩阵中“建议纳入”不是“已经支持并通过”。

| 状态 | 本文含义 |
| --- | --- |
| 已有局部证据 | 指定代码及已记录夹具的历史结果，只能按其范围复用 |
| 已确认核心目标 | 已确认要覆盖的环境家族；版本及其他条件按待决策项补齐，取得目标环境验收前不声明通过 |
| 建议纳入的其他范围 | 设备、辅助技术、宿主及视觉等具体建议尚需确认，不随浏览器家族决定自动生效 |
| 扩展候选 | 是否纳入、优先级和退出标准仍待决定；不因同内核或相近尺寸自动继承通过 |
| 当前合同不支持 | 当前会话/接入契约明确不提供；不得为满足矩阵而放松安全边界 |
| 未验收 / 待冻结 | 证据或范围决定尚缺，不能转换成通过，也不等于已确认产品失败 |

需求方已于2026-10-23确认首批核心家族为Windows 11 Chrome/Edge与macOS Chrome，Safari/Firefox列扩展候选（决策R01）。其余建议仍为“桌面优先、保留窄屏能力、选择代表性嵌入合同”；具体OS/浏览器版本、实体设备、辅助技术、宿主和视觉仍按§8待决策项处理。未收到明确决定的项目不以默认选择、等待时间或本文件代替确认。

### 3.2 会话及浏览器能力门槛

以下是当前实现/合同约束，不是等待浏览器范围确认后才成立的可选项。依据：[浏览器会话设计](browser-session-design.md)、[协调器实现](../web/embedded/browser-session.ts)、[私网开发接入](development-private-http.md)。

| 接入方式 | 必须保留的门槛 | N0如何划分支持 |
| --- | --- | --- |
| 完整Cookie模式 | 同源浏览器/API；可信origin及对应外层Cookie Path；HttpOnly/SameSite等规则；可读写localStorage非敏感协调标记及`navigator.locks.request`；安全随机数。访问令牌在内存，刷新凭证不进入脚本存储 | HTTPS和原显式回环HTTP沿当前合同；目标浏览器需实测跨标签轮换/退出及阻断，并核对下述同host多入口Cookie隔离。存储或锁不可用时应明确失败，不降级成无锁刷新 |
| 私网HTTP开发登录 | feature、debug门禁和宿主显式选择同时满足，可信规范RFC1918 IPv4、同源；服务端提供`development_login`；禁止restore/refresh | 仅隔离开发/测试范围，不作为生产网络方案。重载/到期需重登；不通过query、Host或浏览器能力猜测启用。`0.0.0.0`不是浏览器origin |
| 原显式令牌 / 自定义transport | 保留客户端与宿主可信认证、设备证明及用途边界；不将业务凭证给管理组件 | 仅在选择该交付面的宿主合同下验收；不能自动替代独立后台的Cookie配置，也不自动成为Cookie不可用时的降级 |
| 跨标签与身份 | 同一入口/用途共享一个当前浏览器会话；管理/业务分开；本期不支持多标签同时处于不同业务租户 | 目标矩阵须覆盖sessionChanged、refresh等待、旧响应丢弃和停止旧写入；不以支持多标签推导任意多租户并行 |
| 跨站、跨应用及设备恢复 | 当前不提供第三方Cookie、统一跨应用SSO或设备绑定浏览器恢复 | 当前合同不支持；N0不新增跨源CORS、iframe登录或证明降级契约 |

**同host多入口的命名空间门槛**：Cookie不按端口隔离；即使两个页面的origin因端口不同而不同，同host下同名且同Path的Cookie仍可能互相覆盖。相反，localStorage及协调器锁按包含端口的origin区分；“锁键不同”不能证明Cookie已隔离。不同宿主入口须按既有合同配置不同Cookie名称及相应外部Path，并核对管理/业务purpose、入口client与协调键；Path是发送范围，不是授权边界。启用browser的H01/H02/H03以及使用Cookie的H04/H05都需登记入口共存关系。历史四宿主在独立浏览器上下文中的通过，不扩大为同一浏览器中任意多端口部署互不影响的证据；本轮不新增部署或多产品装配。

普通API的403保留仍有效会话、401按原client清理；restore/refresh失败及跨标签变化按原协调机制处理，不能套用普通读取重试。选择某个浏览器不表示可以豁免这些规则。隐私/企业策略、存储禁用和无痕模式需作为单独环境条件登记；未选定及未测时不作承诺。

## 7 验收分级及支持声明规则

### 7.1 分级定义

| 级别 | 证明什么 | 所需证据 / 当前状态 |
| --- | --- | --- |
| A0：设计与静态/构建检查 | 字段、合同、类型/产物入口、依赖及样式边界可核对 | UI-A与既有Web/嵌入构建等各有历史记录。本N0仅做文档与静态一致性检查，不冒称重跑构建 |
| A1：隔离真实服务与浏览器任务 | 指定参考宿主、模式、真实数据库及浏览器下的业务/隔离行为；注入故障明确标记 | UI-B–F、参考宿主及定向Postgres结果按历史范围使用，未覆盖的用例不自动通过 |
| A2：选定目标环境/代表宿主 | 被确认的OS/完整浏览器版本、实体输入或辅助技术、真实嵌入消费者满足选定用例 | 当前未完成该矩阵。需另获N2授权；不得以同引擎、视口模拟或bundle通过替代 |
| A3：试点/部署及运行保障 | 具体拓扑、代理/TLS、容量、监控、Secret与恢复/迁移等运行目标 | 不属于N0；未启动，目标继续待定。A2通过也不自动获得A3结论 |

### 7.2 核心场景与结果判定

核心候选矩阵的场景至少包括：

1. 登录/Choose、restore/refresh或开发模式的明确拒绝、退出及跨标签变化；管理/业务双向隔离。
2. 四策略工作区和原任务入口、合法/未知/越界hash、刷新与前进后退、目标切换不改变平台身份。
3. 客户端、租户/初始管理员、成员/角色/权限、全局账号、设备/绑定、目标域会话、审计/诊断的适用代表任务；保护管理员、状态及作用域负例。
4. 普通401/403、读取失败、写入成功后读失败、未知结果、版本/原状态冲突；延迟响应、草稿/确认/写入离页及会话失效不重放旧写。
5. 键盘到达/离开、Tab/Shift+Tab/Esc、Select与textarea标签、错误关联、成功播报、危险确认和成功回焦；选定真实读屏/缩放和窄屏输入。
6. 非默认挂载、唯一可信meta、assets、Cookie名称/Path及用途协调键；目标组合若包含同host多端口/多入口，必须验证共存时Cookie与协调器隔离，不把端口差异当作Cookie隔离；H04/H05的宿主React/CSS/portal/认证和属性切换边界。

结果使用“通过 / 失败 / 未执行 / 不适用（说明理由） / 已知限制（说明适用面）”。范围是否已确认另列字段，不与结果混写。正式支持声明需要范围已确认、版本/制品登记齐全、所需级别完成；缺证据只能保留待验收或明确收窄声明，不能默认通过。

身份/租户/用途越界、管理员保护绕过、Secret泄漏、未知写入自动重放、旧响应恢复身份等不能作为可接受视觉或兼容例外。交付汇总K01/K02的dot-only限制继续公开：N0不修复也不改变ID语法，未完成N1前不能声称这些标识的全部管理操作可用。范围例外须明确动作、影响及审批记录，不能把安全失败改列“不适用”。

证据记录建议字段：矩阵ID、交付面、客户端OS/架构与完整浏览器版本、服务端/宿主OS/架构及适用的Rust target/features、运行时/容器镜像、安全/存储/TLS组合、包/宿主版本、产品/制品SHA、模式与挂载、Cookie名称/外部Path及入口共存/用途协调键、视口/DPR/输入、用例和结果、复用或新跑、注入点、限制、审阅人/日期。脱敏后入库，凭据、私有fixture状态、URI与宿主日志不作为公开证据附件。
