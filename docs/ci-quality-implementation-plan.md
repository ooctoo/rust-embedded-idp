# CI质量分层实施计划

> 实施进展（2026-10-26）：P0–P4及P5文档入口已实现，当前验证与复审见[实施记录](ci-quality-implementation-result.md)。远端验证、可选tag规则及远端策略不在本轮授权内。

设计日期：2026-10-25，复审更新：2026-10-26。依据：[详细设计](ci-quality-design.md)。下列阶段保留实施顺序与验收标准，不再表示代码仍未开始。

## 阶段与验收

| 阶段 | 工作与文件范围 | 完成条件 |
| --- | --- | --- |
| P0 当前文档收敛 | 新设计/计划、README、旧CI方案/拓扑/交付文档及工具说明 | 单一当前入口；过量推进标记撤出；历史结果不改写 |
| P1 用例清单和命令 | 盘点crates测试、scripts/test_*、live_*、web测试、N2断言；维护一份合同映射表 | 每个I01–I06/E01–E06有现存测试或明确缺口、执行命令和责任层；识别ignored/skip，不虚报覆盖 |
| P2 构建与UT基线 | .github/workflows/ci.yml及必要的现有离线工具测试入口 | 保留默认/开发feature/release专项、Web类型与bundle、示例构建；源码问题仍能使job失败；不机械删除相似命令 |
| P3 真实集成入口 | 现有run_live_postgres_checks.sh及live_*；必要时小型CI夹具适配；ci.yml integration job | 显式URI、隔离PG、真实执行数可核对；I01–I06覆盖映射成立；失败及清理路径有效 |
| P4 关键E2E | 现有浏览器helper/已修复回归，增加独立关键流程入口与结果；ci.yml e2e job | E01–E06按合同覆盖；直接运行参考宿主；新选集独立命名；完整N2严格门槛不变 |
| P5 统一质量说明及可选tag入口 | ci.yml、README/CONTRIBUTING及测试说明 | PR/main质量集合明确；另授权后才添加release/x.y.z质量触发；无N2全量或生产部署隐式绑定 |

P1先明确现有能力，P2→P3→P4依次闭合后再进行P5。不能因某项复杂就先将skip或continue-on-error写入CI。每阶段按实际审阅SHA验证；并行进行的产品/API变化不自动纳入已完成结论。

## P1具体盘点方法

对现有每组检查登记：所属层、验证合同、命令、features/profile、是否真实PG/HTTP/浏览器、数据生命周期、结果位置、预计影响面。安全断言按语义列出，不能只登记数量。已有N2中工具解析、等待竞态、权限按钮名称和finally落盘修复需要继续有对应回归。

迁移wrapper离线测试归UT/工具检查；真实SQL约束/初始化/迁移行为归集成。前端客户端模拟HTTP属于UT，真实浏览器＋宿主＋PG才属于此计划的E2E。调用边界的重复覆盖可以保留，同层同条件重复命令才考虑合并。

只删除已证明重复、失效或越出设计范围的推进项；删除测试代码需要列出原合同由谁继续覆盖。当前不删除任何历史测试或证据。

## 后续验证安排

1. 先静态检查配置、命令映射、依赖锁定、失败传播和资源所有权，再运行相应离线测试。
2. 获准实际实施/测试后，P3使用全新本地隔离PG验证成功、错误凭证、缺配置、测试失败及清理失败；未显式配置URI必须明确失败/未执行，不能空跑成功。
3. P4使用新数据/profile验证正向和负向场景、超时及退出收尾；修改UI时不依赖人为加长等待。现有公共helper若影响旧N2，先跑离线回归，必要实际专项另行安排。
4. 获准远端执行后，以固定SHA跑一次完整新CI链路，核对实际环境、执行数、日志与artifact、清理；不以本地mock代替远端证明。
5. tag规则先离线检查合法/非法名称、删除/改写、版本与SHA关系；实际推送tag不属于测试脚本默认行为，单独授权。任何阶段不触发生产CD。

## 剔除清单与迁移处置

| 原推进项 | 当前处置 |
| --- | --- |
| N2作为所有PR/版本必跑、固定64组公共套 | 撤出；关键E2E独立设计，完整N2手动保留 |
| 自动路径分类、动态选套协议、N2 workflow_call统一编排 | 撤出；首版采用固定质量集合，无自动分类器 |
| arm64/Debian作为生产制品标准 | 撤出；原组合仅历史专项，新CI环境仅测试选择 |
| Docker缓存、复杂builder、分片 | 撤出当前计划；仅测量后可能单独评估普通依赖缓存 |
| 完整附件每轮写Git | 停止作为常规要求；旧证据保留，新日常附件留Actions |
| 生产镜像、CD、灰度/回滚、生产矩阵 | 下游仓库负责，不在本仓库排期 |
| 缩放、旁白、M1-03–06 | 不进入本计划 |

旧方案保留历史阅读价值，但不继续充当执行授权。README和当前设计为入口；旧文档页首指向替代设计，不重写封存JSON、ZIP或历史成功/失败记录。

## 风险、回退与完成边界

关键风险是把真实数据库测试误当UT、提取E2E漏掉安全断言、异步等待不稳及结果成功但清理失败。分别通过覆盖映射、保留负向断言、事件/响应等待和统一失败传播处理；不建立新的通用测试平台。

新增job出现基础设施问题时可以暂不纳入必需门槛，但必须明确“未启用/未通过”，保留现有CI；不能将失败伪装为成功。新增检查名加入分支保护或变更远端策略需单独确认。保持可逐阶段回退，历史证据不删除。

本轮交付为质量分层实现、测试、文档与本地复验；仅提交相关测试/工具/workflow、已说明的PG缺陷修复与文档，保留无关修改。远端CI通过声明须等待另行授权的真实运行。手动N2暂留原因与退出条件见设计第4节，不再作为长期必做层。
