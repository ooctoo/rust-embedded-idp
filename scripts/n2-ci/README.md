# N2 CI tool inputs

This private package belongs only to the [N2 functional regression workflow](../../.github/workflows/n2-functional.yml). It adds no product dependency. The [approved plan](../../docs/management-console-n2-github-actions-functional-plan.md) defines the functional scope; zoom, VoiceOver, mobile layouts, visual grading and M1-03–06 remain excluded. This directory and workflow are implementation inputs, not evidence that CI or the product suites have passed.

## Frozen tools

- Shell tools: Node **22.23.4** and pnpm **10.30.1**. CI checks both exact versions. The Actions runtime described below is separate from the shell Node version.
- The only direct package dependency is **playwright 1.64.1**. The pnpm 9.0-format lock records `playwright-core 1.64.1` and both registry SHA512 integrities. It was generated by pnpm 10.30.1 with `install --lockfile-only --ignore-scripts`; package resolution did not install dependencies, browsers or system packages. Lock generation used local Node 24.19.0, which emitted the expected engine warning; this does not claim that Node 22.23.4 was exercised locally.
- A future authorized workflow uses `install --frozen-lockfile --ignore-scripts --config.engine-strict=true`, then the local CLI: `pnpm --dir scripts/n2-ci exec playwright install --with-deps --no-shell chromium`. No `npx`, alpha package, user browser or cross-run cache is used.
- The paired full Chromium is **revision 1248 / 156.0.8078.4**, selected with `channel: 'chromium'`, `headless: true`; the driver must verify the installed package/browser rather than fill proposed values into runtime evidence. See the [stable release](https://github.com/microsoft/playwright/releases/tag/v1.64.1), its [browser manifest](https://raw.githubusercontent.com/microsoft/playwright/v1.64.1/packages/playwright-core/browsers.json), and [full Chromium installation guidance](https://playwright.dev/docs/browsers).

Changes to tools or browser versions require a reviewed package/lock/workflow change, not an automatic update during CI.

## Execution and evidence boundary

The workflow is dispatch-only, has one `ubuntu-24.04-arm` job with a 120-minute ceiling, `contents: read`, no persistent checkout credentials, and workflow/ref concurrency without automatic cancellation. It installs no shared cache, registry publishing step, deployment, PR trigger, external database or runner service. Dispatch requires the workflow on the remote default branch and separately authorized remote changes and actual execution.

Private work and browser downloads are under `RUNNER_TEMP/idp-n2-ci-<run>-<attempt>` (0700), with an independent public whitelist at `RUNNER_TEMP/n2-public/<run>/<attempt>` (0700). The driver owns the `prepare`, `run`, `finalize` and `verify` contract and must preserve the overall deadline for cleanup and upload. Per-step timeouts are upper bounds, not a promise that their sum fits inside the job ceiling or measured CI durations.

`finalize` and upload are bounded `always()` steps. A nonzero finalizer preserves safely published failure evidence only when `publication.json` declares schema 1 and `sanitized: true`, lists exactly all other public files with valid relative paths and matching SHA256 hashes, the final summary records failure, and the root/ancestors/files have no symlinks. An unsealed, altered or incomplete publication is replaced by only a constant, secret-free `bootstrap-failure.json`, recording incomplete execution and unknown cleanup. The original nonzero status remains in either case; a failed summary alone is not a safety seal. If the exact run/attempt root cannot be validated, no upload path is supplied. The artifact name includes checkout SHA, run ID, attempt and architecture, with `if-no-files-found: error`, hidden files excluded and 30-day retention. Only the driver's sanitized public whitelist is uploaded. Final verification requires a valid exact-file SHA256 publication seal, all eight matching execution/coverage/raw-result sets, preparation attachments, matching checkout/tool source identities, successful upload and a nonempty artifact ID. Re-sealing an incomplete pack cannot pass. Context/browser cleanup and page errors prevent coverage completion. Process-record read/parse uncertainty fails closed in CI. Driver and workflow initialization validate the exact run/attempt paths and reject symlinks before writing directories. Failure/cancellation/runner loss cannot be converted to success by cleanup or an empty artifact; no `continue-on-error` or error-ignoring shell suffix is used.

Thirty days is the requested retention, not an observed expiry. Existing action outputs (artifact ID, URL and digest) feed the job summary without adding token permissions. The effective `expires_at` remains pending until an authorized reviewer checks the first actual upload and archives that read-only metadata. Full evidence archival is not formally signed off before that check; an offline test or a successful upload cannot fill in an invented expiry.

The local task may resolve npm metadata, validate the lock and run mock/offline tooling checks. It does not dispatch this workflow, download Chromium, start Docker/Postgres or run actual product acceptance.
